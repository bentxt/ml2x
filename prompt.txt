## 2. WHAT fs2ml/ocamlsharp ACTUALLY IS (from docs already read)
================================================================

IMPORTANT NAMING: The project renamed itself. Internally it is now **ocamlsharp**
(dune `(name ocamlsharp)`, package `ocamlsharp`). Historical names: `fs2ml`,
`fsharp2ocaml`, `eocaml`, `JavaML`/`javaml`. The handoff.md in THIS repo calls it
"fs2ml"; the source repo calls it "ocamlsharp". Same thing.

WHAT IT IS (per its README + handoff-fs2ml.md):
  A source-to-source PREPROCESSOR, NOT an F# compiler:
    "write OCaml with an F#-shaped syntax -> emit readable OCaml
     -> let ocamlc/dune typecheck it"
  OCaml is the semantic authority. Not aiming for F#/.NET compatibility.

PIPELINE (current, per handoff-fs2ml.md "Important Caveat"):
    JavaML parser / AST  ->  syntax-only backend hook  ->  src/esca_ocaml/emit.ml  ->  OCaml
  i.e. it STILL REUSES the JavaML parser and AST (vendored from Esca's JavaML
  frontend). The README confirms: "The src/ frontend (lexer/parser/AST) is
  vendored from Esca's JavaML frontend and carries no dependency on it."
  The handoff calls this "not the right long-term ownership" and wants a
  future "fs2ml parser/AST -> lightweight normalization -> OCaml emitter".

  NOTE: handoff-fs2ml.md describes an OLDER layout (src/esca_ocaml/, tools/,
  t/esca-ocaml/, make check-esca-ocaml) that is STALE. open-problems-plan.md
  Phase 1 flags this. The CURRENT layout (per README) is:
    src/  ocamlsharp library: diagnostic, token, lexer, ast, parser, pipeline, emit
    bin/  ocamlsharp (forward .fs -> .ml)
          ocaml2ocamlsharp (reverse .ml -> .fs, OCaml >= 5.2 only)
    test/ core.fs, core.ml, core.reverse.fs
    demo/ demo.fs, demo.ml
  Forward lib/bin are pure stdlib (OCaml 4.14+). Reverse tool reads compiler-libs
  parsetree (uses Obj to inspect internals; tuple/function payloads need 5.2+;
  gated by dune enabled_if).

SUPPORTED SUBSET (checked fixture, per README + handoff):
  one module; records; variants; typed `let rec` functions; local `let ... in`;
  `match`; `if`; record/constructor values; local calls; tuples; lists;
  arrays (emitter only); basic operators. Anything outside -> diagnostic.

PARSE SURFACE IS WIDER THAN EMITTED SUBSET (per open-problems-plan.md Phase 2):
  The parser/AST still ACCEPT JavaML-era constructs that the OCaml emitter REJECTS
  later, e.g. `new`, object declarations, imports, packages, throws, loops,
  try/catch, assignment, member calls, indexing. Emitter errors like
  "OCaml syntax emitter does not support Java-style method calls".
  -> This is directly relevant to the handoff's OO/Java-DSL questions:
     there IS existing OO-ish parse machinery, but it's legacy JavaML syntax,
     not F# object syntax, and it does not map to OCaml objects.

CHECK / VERIFICATION:
  `sh check.sh` -> core.fs -> core.ml -> ocamlc; and on OCaml >= 5.2 the reverse
  roundtrip core.ml -> core.reverse.fs -> core.ml -> ocamlc.
  (When resuming, consider running `sh check.sh` to confirm it still passes,
   but do NOT modify the fs2ml repo.)
